# TURNitURE — Turn It Yours

졸업 프로젝트 웹사이트. `Reference/` 폴더의 시안(1920 × 1080)을 기준으로 만든 정적 사이트입니다.
프레임워크 없이 HTML / CSS / JS 만 사용합니다.

## 구조

| 파일 | 설명 |
|---|---|
| `index.html` | 전체 마크업 (헤더 · 메인 · Images/Sounds 페이지 · Color 패널) |
| `styles.css` | 레이아웃과 색. 1920 × 1080 아트보드 좌표를 그대로 사용 |
| `app.js` | 탭 전환, hover, 캐러셀, Color 패널, 커스텀 커서 |
| `intro.js` | 메인 화면 타이틀 시퀀스 (루프) |
| `make.js` | Let's Make 단계 — 입력 · 분석 · 배치 · Top/3D · 타임라인 |
| `shapes.js` | 가구 실루엣(기본 패스 + 호버 클러스터) + 컬러 팔레트 |
| `logo.js` | 로고 SVG를 문자열로 inline. `fill="currentColor"`라 색이 따라옴 |
| `icons.js` | `Icon/`의 SVG를 문자열로 inline (Profile · Cart · Trash · Ticket) + 카메라 · X |
| `profile.js` | Profile 페이지 — 사진 찍기/고르기, EDIT 잠금 해제 |
| `cart.js` | 담은 것들의 모델. DOM을 모름 (목록 · 수량 · 금액 · 쿠폰) |
| `checkout.js` | Cart 페이지 1~4단계 — 바닥 배치 · 빌지 · 주소 · 카드 · 영수증 |
| `assets/logo.svg` | 같은 로고의 파일 버전 (참고용) |
| `m/index.html` | **모바일 전용** 마크업. 데스크탑과 같은 훅을 써서 `make.js`를 그대로 씀 |
| `m/styles.css` | 모바일 레이아웃. 390 폭 아트보드 좌표 |
| `m/app.js` | 모바일 탭 전환, 탭-투-오픈, 스와이프, Color 패널 |
| `Video/` | 메인 화면에 깔리는 영상. `main-loop.mp4`가 페이지가 쓰는 파일 |
| `Icon/` | 헤더·버튼에 쓰는 아이콘 원본 SVG |
| `Reference/` | 작업 기준이 된 시안 이미지 |

`shapes.js` · `logo.js` · `icons.js` · `intro.js` · `make.js` · `cart.js` ·
`profile.js` · `checkout.js`는 데스크탑과 모바일이 **같은 파일을 공유**합니다.
모바일 쪽 마크업이 데스크탑과 같은 훅(클래스 · `data-*` · id)을 쓰기 때문이고,
고치면 양쪽에 함께 반영됩니다. 모바일 전용은 `m/index.html` · `m/styles.css` ·
`m/app.js` 셋뿐입니다.

## 화면

- **메인** — 두 화면 깊이입니다 (아래 참고)
  - 처음 보이는 것은 **영상**, 화면을 꽉 채우고 무한 반복합니다
  - **아래로 스크롤하면** 그 밑에서 타이틀 시퀀스가 올라옵니다
  - 좌상단 로고를 누르면 어디서든 메인(영상)으로 돌아옵니다
- **Image / Sound** — 내용은 동일하고 탭과 제목만 다름
  - 제목은 탭마다 고정: `Turn your image into` / `Turn your sound into`
  - 항목 5개 (Side Table · Tray · Wall Shelves · Stool · Pendant) 중
    4개씩 보이고, 좌우 화살표로 한 칸씩 이동합니다
  - 항목을 누르면 만들기 단계로 넘어갑니다 (6종 전부)
  - 항목에 마우스를 올리면 박스가 가운데에서 부드럽게 열리면서
    상세 형상과 치수가 나타납니다
  - 이때 형상 안의 요소들이 각각 길이·너비를 계속 바꿉니다 (아래 참고)
- **Colors** — 14개 색상이 위에서 아래로 차례대로 내려옵니다
  - `1` = 글자·도형 색 (foreground), `2` = 배경 색 (background)
  - 색을 누를 때마다 `1` → `2` → `1` … 순서로 지정됩니다
  - 처음 들어올 때의 두 색은 **매번 무작위로 뽑습니다**
  - 칩 뒤쪽 배경에는 progressive blur가 걸립니다 (왼쪽 0 → 오른쪽 최대).
    세기는 `styles.css`의 `--blur-max` 한 값으로 조절합니다
  - 칩은 보이는 크기(46px)를 유지한 채 클릭 영역만 58px 원으로 넓혔습니다
    (칩 간격이 60px이라 서로 겹치지 않습니다)
  - 맨 아래 X, `Colors` 탭, 또는 빈 영역을 클릭하면 닫힙니다
- **Profile** — 헤더 오른쪽 사람 아이콘 (아래 참고)
- **Cart** — 그 옆 장바구니 아이콘. 결과 화면에서 담은 것들이 모입니다 (아래 참고)

## 메인 화면 — 영상과 타이틀

`Reference/Main_Video`. 메인은 **두 화면 깊이**입니다. 처음 만나는 것은
영상이고, 예전에 혼자 있던 타이틀 시퀀스는 그 한 화면 아래에서 기다립니다.
휠·화살표키·스페이스, 또는 아래쪽 꺾쇠를 누르면 영상이 위로 빠지면서 타이틀이
따라 올라옵니다. 위로 올리면 영상이 다시 앞에 섭니다.

**영상은 아트보드가 아니라 창에 붙입니다.** 스테이지는 1920 × 1080 고정
상자라 창 비율이 다르면 레터박스가 생기는데, 영상은 모든 모서리에 닿아야
하므로 `position:fixed`로 창에 깔고 `object-fit:cover`로 **창 비율에 맞춰
잘라냅니다.** 그래서 21:9든 세로 핸드셋이든 빈 틈이 없습니다.

**무한 반복**이고 `muted` + `playsinline`입니다 — 브라우저가 영상을 스스로
틀어 주는 조건입니다. 저전력 모드처럼 그래도 거부하는 경우가 있어
`play()`의 실패는 그냥 넘깁니다 (배경색만 남고 나머지는 멀쩡합니다).

**지금 보이는 것만 돕니다.** 타이틀 쪽에 있으면 영상을 멈추고, 영상 쪽에
있으면 시퀀스를 멈춥니다. 메인을 떠나면 둘 다 멈춥니다.

> `.page--home`은 위아래만 잘라냅니다 (`clip-path: inset(0 -2000px)`).
> 한 화면 아래에 둔 타이틀이 레터박스 영역에 비치면 안 되지만, 글줄이
> 자간을 벌릴 때 좌우로는 아트보드를 넘어갈 수 있어서입니다.

**영상 파일** — 원본 `Video/01_Web.mp4`는 1920×1080 22.5초에 43MB라
한 번 열 때마다 43MB를 받습니다. 페이지가 쓰는 것은 같은 영상을 720p로
다시 뽑은 **`Video/main-loop.mp4` (19MB)**이고, 원본은 `.gitignore`에
넣어 저장소 밖에 둡니다. 더 가볍게 하려면 같은 자리를 바꿔 끼우면 됩니다.

## 메인 타이틀 시퀀스

`intro.js`. 한 바퀴 약 7초이고 계속 반복합니다. 메인에서 아래로 내려가야
보입니다.

1. `Furniture?`를 한 글자씩 F→u→r→n→i→t→u→r→e→? 순서로 찍습니다.
   가운데를 기준으로 양옆으로 자라납니다
2. 찍는 동안 글자마다 서체가 계속 바뀝니다. 한 번 섞을 때마다 서체 풀을
   섞어서 앞에서부터 나눠주므로 **같은 서체가 두 글자에 동시에 걸리지 않습니다**
   (서체 16종 ≥ 글자 10개)
3. 마지막 글자가 놓이면 전부 Avenir로 정렬됩니다
4. `Furniture?`가 빠지고 `Turn It Yours`가 들어옵니다 (Avenir)
5. `Turn It Yours`가 TURNitURE 로고로 넘어갑니다

구현 메모
- 글자 칸의 너비는 Avenir 기준으로 고정했습니다. 서체가 바뀌어도 글리프만
  바뀌고 줄이 좌우로 떨리지 않습니다
- 서체마다 같은 font-size에서 캡 높이가 달라 "협박편지"처럼 보이기 때문에,
  각 서체의 캡 높이를 한 번 측정해 Avenir에 맞게 보정합니다
- 가운데 정렬은 줄 너비의 절반만큼 px로 옮기는 방식이라, 글자가 늘어날 때
  부드럽게 따라갑니다 (`translateX(-50%)`는 전환이 걸리지 않습니다)
- `Turn It Yours`와 로고는 캡 높이·너비가 비슷하게 맞춰져 있어서
  크로스페이드만으로 바뀌는 느낌이 납니다
- 타이밍은 `intro.js` 맨 위 `T` 객체 한 곳에 모여 있습니다
- Image/Sound 탭으로 가면 멈추고, 메인으로 돌아오면 다시 시작합니다
- `prefers-reduced-motion: reduce`면 로고 상태로 고정합니다

## Let's Make — 만들기 단계

목록에서 항목을 누르면 입력 화면으로 넘어갑니다.
이 화면만 팔레트가 반대로 뒤집힙니다 — `Tray_01.png` 그대로입니다.

**입력** — 두 가지 중 하나
- `Drop Image` / `Drop Sound` — 파일을 끌어다 놓거나 눌러서 고르기
- `Live Image` / `Live Sound` — 한 번 누르면 카메라가 켜지고(또는 녹음 시작),
  다시 누르면 찍힙니다(또는 녹음 종료)

**변환** — `코딩 2` 프로토타입의 분석을 그대로 따릅니다.
프레임 하나가 `{ vol, depth }`이고,

| 입력 | 지름 | 높이 |
|---|---|---|
| 이미지 | 채도 | 명도 |
| 소리 | RMS 음량 | 100–800 Hz 주음 |

- 값 자체가 아니라 **그 입력 안에서의 순위(백분위)**로 배치합니다.
  값으로 늘리면 조용한 녹음은 전부 얇게, 시끄러운 녹음은 전부 굵게 뭉칩니다
- 앞 프레임과 가장 많이 달라진 순간들만 골라 씁니다
- 소리는 모노로 합친 뒤 8 kHz로 내려서 자기상관으로 주음을 찾습니다.
  100–800 Hz만 보면 되므로 이 정도면 충분하고, 전체 녹음을 훑어도 빠릅니다

**제품** — 5종

| | 대지 | 배치 | 형상 | 지름 | 높이 | 개수 |
|---|---|---|---|---|---|---|
| Side Table | Ø400 | 황금각 나선 | 아래가 둥근 기둥 | 50–150 | 200–700 | 22 |
| Tray | 260×260 | 3×3 격자 | 끝이 뾰족한 원뿔 | 60–130 | 40–160 | 9 |
| Wall Shelves | 700×150 | 벽을 따라 한 줄 | 반으로 가른 타원 반구 | 100–300 | 60–240 | 7 |
| Stool | 380×380 | 4×4 격자 | 직육면체 | 가로·세로 55–95 | 60–450 | 16 |
| Pendant | 500 | 가로 한 줄 | 선에 매달린 원뿔 | 60–140 | 80–250 | 5 |

- **Side Table** — 평평한 윗면이 한 평면에 맞춰지고 둥근 아래 끝이 제각각
  다른 높이에 옵니다. 바깥쪽 4개는 길이를 맞춰 다리가 됩니다
- **Tray** — 뾰족한 끝이 모두 바닥에 닿고 높이 차이가 윗면으로 드러납니다
- **Wall Shelves** — 벽에 붙는 반구. 앞으로 나온 폭이 곧 반지름이라
  지름 최대 300 = 돌출 최대 150입니다. 위에서 보면 반원입니다
- **Stool** — 윗면이 한 평면에 맞춰집니다. 그 평면이 앉는 면이고,
  네 모서리가 최대 길이로 내려와 다리가 됩니다
- **Pendant** — 천장 한 면에서 저마다 다른 길이로 내려옵니다.
  어깨끼리 물리게 붙여서 5개가 각각 보이도록 했습니다

**겹치는 정도** — 프로토타입의 세 규칙을 그대로 옮겼습니다. 이게 없으면
나선은 한 덩어리로 뭉치고 격자는 조각이 떠 버립니다.

- **Side Table / `spreadToMaxOverlap`** — 어느 쌍도 가는 쪽 지름의 20%보다 깊이
  박히지 않습니다. 전체를 한 배율로 벌리면 제일 심한 한 쌍 때문에 결과물이
  두 배가 되므로, 넘치는 쌍만 조금씩 밀어 되풀이합니다
- **Side Table / `forceSupportLegs`** — 바닥에 닿는 4개를 사분면마다 하나씩,
  각 사분면에서 가장 바깥 것으로 고릅니다. 그냥 '가장 바깥 4개'로 하면
  한쪽에 몰려 테이블이 기웁니다
- **Tray / `connectStrays`** — 격자 자리는 건드리지 않고(모서리를 끌어오면
  네모가 십자가 됩니다) 가는 쪽만 굵혀서, 이웃 쌍마다 최소 3 mm씩 물리게
  합니다. 이웃은 '가장 가까운 간격의 1.3배 안'이라 격자에서는 가로·세로
  쌍이고 대각선은 빠집니다
- **Tray / 칸 크기** — 9개가 대지를 꽉 채우도록 `√(260²/9) = 86.7 mm`.
  지름이 60–130이라 굵은 것끼리는 겹치고 가는 것은 위 규칙이 붙입니다
- 격자는 가운데에서 바깥으로 채웁니다. 짧은 입력이 와도 가운데가 비지 않습니다

> 프로토타입은 두 형상이 닿는지를 높이를 훑어가며 봅니다(원뿔은 가장 넓은
> 단면이 서로 다른 높이에 있으므로). 여기서는 가장 넓은 단면끼리의 평면
> 거리로 봅니다 — Top View에 보이는 것과 같은 기준입니다.

## 결과 화면

`ImageConvert_1/2`, `SoundConvert_1~3` 시안입니다. 입력 단계와 달리 팔레트는
원래대로 돌아오고 제목은 사라집니다.

**왼쪽 — 무엇이 들어갔는지**
- 이미지: 사진을 그대로 띄우고, 각 형상이 읽힌 **구역을 실선으로 나눕니다**.
  재생 중에는 지금 짚는 구역을 키컬러 60%로 덮습니다
- 소리: 사진이 없으므로 **같은 결과물을 위에서 본 모습**이 들어갑니다.
  형상이 하나씩 자기 자리에 놓이고, 지금 만들어지는 자리에서는 점들이
  로딩처럼 돕니다
- 소리는 재생하면 **실제로 들립니다.** 그리고 지금 짚는 형상이 지금 들리는
  부분이 되도록, 재생 머리가 녹음 자체의 시간을 따라갑니다
- 아래 **슬라이더로 녹음을 넘겨볼 수 있습니다.** 긴 녹음을 형상 하나씩
  따라가기는 번거로워서입니다. 끌면 음성과 양쪽 화면이 같이 그 지점으로
  가고, 재생은 바를 둔 자리에서 이어집니다 (끝에 있으면 처음부터).
  이미지에는 넘길 시간축이 없으므로 나오지 않습니다

**오른쪽 — 무엇이 나왔는지.** 재생 중 해당 형상이 **50% 어두워집니다.**
투명하게 만들었더니 배경에 묻혀 오히려 잘 안 보였습니다.

**버튼** — 재생 / 2D·3D / Cart. Cart는 눌리기만 합니다 (장바구니는 나중에).
소리에는 2D·3D가 없습니다 — 윗면으로 보여 줄 것이 없습니다.

**크기** — 결과물이 만들어질 때 배율을 한 번 정하고 그대로 씁니다. 돌려도
크기가 변하지 않습니다.

배율은 **어느 각도에서도 잘리지 않도록** 잡습니다. 화면에 찍히는 세로
위치가 `-y'·sin(pitch) - z·cos(pitch)`라서, 각도가 어떻든 세로 폭은
`hypot(2G, 높이)`를 넘지 않습니다(G = 중심에서 가장 먼 형상까지).
지금 각도의 크기로만 잡으면 눕혔을 때 캔버스 밖으로 나갑니다.

기준은 바닥면이 아니라 **결과물 자신의 가운데**입니다 — 그리기가 가운데
정렬이라, 바닥에서 재면 두 배로 넉넉해져 쓸데없이 작아집니다.
여유는 `make.js`의 `SHARE` 한 값으로 조절합니다.

**가려짐** — 형상은 모두 같은 수직축을 따라 서거나 매달려 있으므로,
무엇이 무엇을 가리는지는 **바닥에서 정해집니다.** 눈이 앞에 있으니 기울기가
어떻든 바닥 깊이가 작은 쪽이 가깝습니다. 높이는 한자리에 쌓인 경우를 위한
동점 처리에만 씁니다.

> 높이를 깊이 값에 섞었더니 Side Table이 엉켰습니다. 윗면은 한 평면인데
> 길이는 제각각이라, 긴 기둥이 '멀리 있는 것'으로 정렬되어 이웃의 윗면이
> 그 위에 얹혔습니다.

**평평한 면은 그 면 쪽에서 볼 때만 그립니다.** 기둥·원뿔·돔의 윗면은
위에서 내려다볼 때, 펜던트의 아래 입구는 아래에서 올려다볼 때만 보입니다.

**형상은 고정된 실루엣이 아니라 진짜 입체로 그립니다.** 박스를 뺀 나머지는
전부 볼록하므로, 표면 점을 투영해 **볼록 껍질**을 두르면 그게 곧 그 각도에서의
윤곽입니다. 고정 실루엣은 한 각도에서만 맞아서, Side Table과 Tray를 아래에서
보면 납작해졌습니다. Stool만 멀쩡했던 건 그것만 진짜 면으로 그리고 있었기
때문입니다.

**Wall Shelves의 반구**도 같은 방식입니다. 잘린 평면이 있어 회전 대칭이
아니므로, 반쪽 타원체의 표면(곡면 + 자른 면)을 함께 찍어 껍질을 두릅니다.
덕분에 돌리면 잘린 면의 방향이 같이 돕니다.

**Stool은 상자마다 너비·깊이·높이가 다 다릅니다.** 가로는 음량, 세로는
음높이, 길이는 둘을 곱한 값의 순위로 잡아서 세 치수가 따로 놉니다.
칸 크기는 그 열(행)에서 **가장 작은** 상자에 맞춥니다 — 그러면 어떤 상자도
제 칸보다 좁지 않아 이웃과 반드시 맞닿습니다. 가운데 빈틈은 생겨도 되지만
떨어져 나가는 조각은 없습니다.

> 칸을 꽉 채우게 했더니 한 열이 전부 같은 너비가 되어 통짜 덩어리처럼
> 보였습니다.

**Wall Shelves는 잘린 뒷면이 전부 한 평면에 있습니다.** 각자 반지름만큼
앞으로 밀어 놓았더니 굵은 것이 더 튀어나와 뒷면이 계단처럼 어긋났습니다.
벽에 붙는 물건이라 그 면은 반드시 한 평면이어야 합니다.

**기둥의 둥근 발**은 전체 길이를 균등하게 나눠 찍지 않고 발만 따로 찍습니다.
길이를 나눠 찍으면 첫 고리가 거의 적도에 놓여, 거기서 끝점까지 직선으로
이어져 발이 뾰족해집니다.

**직육면체(Stool)는 실루엣이 아니라 진짜 면으로 그립니다.** 기둥이나 원뿔과
달리 회전 대칭이 아니라서, 돌리면 면도 같이 돌아야 합니다. 꼭짓점 8개를
투영하고 보이는 면만 골라 먼 것부터 칠합니다.

**펜던트는 아래에서 올려다봅니다.** 기울기를 음수로 두면 눈이 결과물 아래로
갑니다 — 전등은 올려다보는 물건이니까요. 끌어서 기울이는 범위도 음수까지
열어 뒀습니다.

**쌓인 층 (G-Code)** — 실험실의 G-Code 미리보기처럼, 결과물 **옆면에 적층선을
긋습니다.** 층 높이마다 그 높이에서 노즐이 도는 단면을 구해서, **보는 쪽으로
돌아선 반쪽만** 그립니다. 그래서 선이 기둥에서는 아래로 휘고 원뿔 끝에서는
오므라듭니다 — 화면에 그은 가로줄이 아니라 그 높이의 진짜 단면입니다.

- 선 개수는 **실제 수치 두 개**로 나옵니다. **층 높이**는 복합도에서 오고
  (0%면 19px, 100%면 5.5px), **개수는 그 형상 자신의 높이 ÷ 층 높이**입니다.
  그래서 같은 복합도여도 긴 기둥이 옆의 짧은 기둥보다 선이 많습니다
- 층 높이는 **화면 px로 두고 고정 배율로 나눕니다.** 결과물이 크게 나오든
  작게 나오든 (카트의 작은 조각, 모바일 캔버스) 선 간격이 같아 보입니다
- 복합도는 그 구간이 바로 앞 구간과 얼마나 달랐는지(`pick`이 프레임을 고를 때
  쓰던 그 값)이고, 다른 값들처럼 **그 결과물 안에서의 순위**로 매깁니다.
  복합도는 **형상을 건드리지 않습니다** — 선의 촘촘함만 정합니다
- **윗면에는 긋지 않습니다.** 뚜껑은 한 층이라 평평하게 깔립니다. 2D(윗면)
  뷰도 같은 이유로 그대로 둡니다
- **Stool(직육면체)도 같습니다.** 단면이 직사각형이니 보는 쪽 반쪽은 보이는
  두 벽을 모서리까지 가로지르는 선이 됩니다
- 보이는 쪽 반쪽은 **투영한 단면의 볼록 껍질 한 변**으로 구합니다 — 내려다보면
  아래쪽 변, 올려다보면(펜던트) 위쪽 변. 가까운 점만 골라 정렬하면 모서리가
  날아가는데, Stool의 단면은 모서리가 전부입니다

> 처음에는 두 색 띠로 칠해 봤습니다. 배경색으로 칠하니 구멍처럼 뚫려 보여
> 톤을 섞어 봤지만, 실제 G-Code 미리보기는 색 띠가 아니라 **쌓인 선**이라
> 선 긋기로 바꿨습니다.

> 타임라인은 걷어냈습니다. 재생 버튼이 그 자리를 대신합니다.

## 호버 형상의 움직임

항목에 마우스를 올리면 형상 안의 요소들이 **각각 따로** 길이와 너비를 계속
바꿉니다. 배치와 구조는 그대로 두고 크기만 움직입니다.

- 요소마다, 그리고 길이·너비마다 **따로** 랜덤한 목표값으로 천천히 이동합니다
- 이동 시간도 요소마다 달라서(380~1100ms) 다 같이 뛰지 않고 계속 흐트러집니다
- 너비가 바뀌어도 **요소들 사이에 여백이 생기지 않습니다.** 한 줄을 매 프레임
  다시 붙여 쌓는 방식이라, 한 요소가 넓어지면 옆 요소를 밀어냅니다.
  대신 줄 전체의 좌우 폭이 좁아졌다 넓어집니다 (줄 중심은 시안 자리에 고정)
- 시안이 원래 겹쳐 그린 부분(Pendant의 원뿔, Shelves의 링)은 그 겹침을
  그대로 유지합니다. 새로 벌어지는 일만 막습니다
- 올리는 순간은 항상 **시안 그대로의 비율**에서 시작해 거기서 번져 나갑니다
- 마우스를 빼면 원래 비율로 부드럽게 돌아간 뒤 멈춥니다
- 높이는 클러스터 박스를 넘지 않게 잘라서, 크게 움직여도 글자나 박스를
  침범하지 않습니다
- 움직임 폭은 `app.js`의 `SWING_H` / `SWING_W`, 속도는 `LEG`로 조절합니다

이게 가능하려면 호버 형상이 하나의 통 패스가 아니라 **여러 개의 독립된
요소**여야 합니다. 시안을 뜯어보니 호버 형상은 전부 *그 항목의 기본 실루엣을
크기만 바꿔 여러 번 늘어놓은 것*이라, `shapes.js`에서 `unit`(한 개를 그리는
함수) + `units`(배치) 구조로 바꿨습니다.

| 항목 | unit | 개수 | 기준 |
|---|---|---|---|
| Side Table | 끝이 둥근 막대 | 5 | 위 |
| Tray | 아래로 향한 삼각형 (서로 겹침) | 6 | 아래 |
| Wall Shelves | 돔 | 4 | 위 |
| Stool | 막대 | 5 | 위 |
| Pendant | 선에 매달린 원뿔 | 5 | 아래 |

> 카메라·마이크로 실시간 반응시키는 버전도 한 번 만들었다가 뺐습니다
> (`sense.js`, 커밋 `6e8cb8b`). 되살리려면 그 커밋에서 파일을 꺼내
> `app.js`의 drift 자리에 신호값을 넣어주면 됩니다.

## 좌표계

모든 수치는 시안과 같은 **1920 × 1080 아트보드 px**로 적어 두고,
`app.js`가 창 크기에 맞춰 `--k` 배율만 바꿔 줍니다. 그래서 어떤 창 크기에서도 배열이 시안과 같습니다.

## 모바일 버전 (`m/`)

데스크탑 페이지는 1920 × 1080 아트보드를 통째로 축소합니다. 폰에서는 배율이
`min(390/1920, 844/1080)` = **0.20**이 되어 화면 가운데 219px 높이 띠로 눌려
들어갑니다. 반응형으로 고칠 수 있는 차이가 아니라 레이아웃을 따로 짰습니다.

**라우팅** — 루트 `index.html` 머리에 짧은 리다이렉트가 있습니다. 폭이 820px
이하이거나 coarse 포인터(터치)이면서 1024px 이하이면 `m/`으로 보냅니다.
`?desktop=1`을 붙이면 폰에서도 데스크탑 버전이 그대로 열립니다 (크리틱·발표용).

**좌표계** — 폭만 기준으로 잡습니다. 아트보드는 **390 폭**이고 배율은
`min(innerWidth/390, 1.35)`, 높이는 실제 화면 높이를 아트보드 단위로 되돌린
`--vh`로 둡니다. 가로 구성은 모든 기기에서 같고 세로만 기기에 맞춰 늘어납니다.
1.35 상한은 리다이렉트에 걸리는 작은 태블릿에서 과하게 커지지 않게 하는 선입니다.

**카드 크기** — 목록 카드는 데스크탑 카드를 `--s`배 한 것이라 내부 비율은
시안에서 잰 그대로입니다. `--s`는 `app.js`가 창에 남은 높이에서 뽑아 최대 0.70,
좁으면 그보다 작게 둡니다. 짧은 기기에서 카드가 잘리는 대신 작아지게 하려는 것이고,
실루엣 SVG도 같은 `--s`로 크기를 받아 따라옵니다 (viewBox는 추적 당시 단위 그대로라
형상 드리프트 계산은 건드릴 필요가 없습니다).

**메인** — 데스크탑과 같습니다. 같은 영상이 핸드셋 비율에 맞춰 잘려 깔리고,
위로 쓸어올리면(또는 꺾쇠를 누르면) 타이틀 시퀀스가 올라옵니다. 아래로 쓸면
영상으로 돌아옵니다. 영상은 `../Video/main-loop.mp4` 하나를 데스크탑과 같이
씁니다.

**화면 구성** — `Reference/MobileSelect`·`Mobile_LiveImage`·`Mobile_LiveSound`
기준입니다. 로고는 가운데 위(폭 201, y52)에 혼자 있고, 누를 수 있는 것은 전부
**아래 바**에 모았습니다 — Image · Sound · Colors · 프로필 · 장바구니, 높이 36에
화면 아래에서 34 띄웁니다. 엄지가 닿는 자리입니다. 열려 있는 탭은 옵션바 박스가
감싸서 글자가 파여 보입니다.

**첨부 화면** — Let's Make의 입력 단계는 246 정사각형 두 개를 35 간격으로
위아래로 둔 것이고, 로고와 아래 바 사이에 가운데 맞춤입니다. 짧은 기기에서는
두 개가 같이 작아집니다(`--sq`). 시안에 제목이 없어서 `Let's Make …` 줄은
이 단계에서 감춥니다. 첫 박스는 데스크탑과 같이 **Drop**입니다.

**Live Image** — 카메라가 켜지면 박스가 아니라 화면이 됩니다. 뷰파인더가
위를 채우고 삼분할 격자가 겹치며, 아래 동그란 셔터(지름 90, 링 3.5 + 원 70)
하나로 찍습니다. 셔터는 make.js가 이미 아는 "두 번째 누름"을 그대로 넘깁니다.

**Live Sound** — 마이크가 켜지면 들리는 것을 막대로 그립니다. 18칸짜리 줄에
110ms마다 한 칸씩 **왼쪽부터 차오르고** 다 차면 밀려 나갑니다. 값은 창의
RMS이고, 막대는 세로 가운데 정렬입니다. 그 아래 같은 모양의 녹음 버튼이 있습니다.
make.js에 `onLive(fn)`을 하나 더해 스트림이 시작·종료될 때 알려 주게 했고,
데스크탑은 아무것도 등록하지 않아 그대로입니다.

**Profile · Cart** — 데스크탑과 같은 스크립트가 돌고 마크업도 같습니다. 폭만
다시 짰습니다. 장바구니는 "옆"이 없으니 **빌지가 바닥 아래**에 눕고, 2·3단계의
주소·카드 칸도 빌지 아래로 내려옵니다. 바닥과 조각의 크기는 `checkout.js`가
스타일시트에서 **재서** 쓰기 때문에, 두 레이아웃이 각자의 수치를 가집니다.

**호버 대체** — 터치에는 hover가 없습니다. 카드를 한 번 탭하면 치수 박스가 열리고
형상이 흔들리기 시작하고, 한 번 더 탭하면 Let's Make로 들어갑니다. 빈 곳을 탭하면
닫힙니다. 옵션바 박스는 쫓아다닐 포인터가 없으니 탭한 자리에 그대로 멈춰서,
열려 있는 탭을 가리키는 표시가 됩니다. 흰 점 커서는 뺐습니다.

**캐러셀** — 한 번에 한 장만 보여주고 스와이프 · 화살표 · 점으로 넘깁니다.
이동 간격은 카드 폭이 아니라 고정 330px인데, 그래야 옆 카드가 화면 밖에 완전히
서서 다음 라벨 끄트머리가 가장자리에 비치지 않습니다.

**결과 화면** — 좌우 2단이 위아래로 쌓입니다. 버튼 줄과 스크럽 바는 아래 바
위에 올라앉습니다 (각각 84 · 152). 3D 드래그 회전과 스크럽 바는 이미
pointer 이벤트라 터치에서 그대로 동작하고, 캔버스에 `touch-action:none`만 줬습니다.
**가로 모드** — 세로 전용입니다. 가로로 눕히면 "Turn your phone upright"만 띄웁니다.
세 번째 구성을 따로 그리지 않기로 한 선택입니다.

**알려진 제약** — `Live Image` / `Live Sound`는 `getUserMedia`라 HTTPS(또는
localhost)에서만 됩니다. 그 외에는 "No Camera" / "No Mic"으로 떨어집니다.
배포할 때 HTTPS면 문제 없습니다.

python3 serve.py

## 메모

- 본문 서체는 macOS의 **Avenir Next**를 쓰고, 없는 환경에서는 Google Fonts의 Montserrat로 대체됩니다.
- 타이틀 시퀀스의 서체 풀은 Google Fonts 5종 + 시스템 서체 11종입니다.
  시스템 서체가 많은 macOS에서 가장 다양하게 보입니다.
- 로고는 `Reference/Logo.svg`를 사용했습니다. (요청 메시지에는 `Logo.png`라고 적혀 있었지만 폴더에는 svg만 있었습니다. 벡터라 더 선명합니다.)
- 로고와 옵션탭은 두 번 줄여 시안의 56%입니다 (20% → 다시 30%).
  로고 `207 × 30px`, 탭 `40px`, 여백도 같은 비율로 줄였습니다.
- 팔레트는 14색입니다. 들어올 때마다 그중 두 개를 무작위로 뽑아 쓰되,
  **밝기 차가 충분한 조합만** 뽑습니다 — 창백한 색이 둘, 거의 검정인 색이
  셋이라 그냥 뽑으면 글자가 배경에 묻히는 조합이 나옵니다
  (`shapes.js`의 `openingPair`).
- 칩이 8개에서 14개로 늘어 컬럼 간격을 100px → 60px로 좁혔습니다.
  옛 간격이면 마지막 칩이 y=1454로 아트보드(1080) 밖으로 나갑니다.
- 결과 화면의 고정 배율(`measureScale`)은 결과 패널이 **화면에 올라온 뒤에** 잽니다.
  그 전까지 패널은 `display:none`이라 0으로 측정되고, 데스크탑에서는 폴백 수치가
  마침 실제 캔버스 크기와 같아서 드러나지 않던 자리였습니다.
- 모바일 캔버스는 `left/right`로 늘이지 않고 크기를 직접 줍니다. `<canvas>`는
  치환 요소라 width/height **속성**이 고유 크기로 쓰여 `width:auto`면 그 값을 잡고
  반대쪽 offset이 무시되는데, `make.js`가 그 속성을 측정값에서 다시 쓰기 때문에
  서로 물려 매 프레임 두 배씩 커집니다.
- Cart의 조각은 **그림이 아니라 형상**으로 담깁니다. `make.js`가 `snapshot()`으로
  조각 목록과 각도를 내주고 `paint(canvas, snap, flip)`으로 남의 캔버스에도 그려
  줍니다. 그리는 동안만 내부 상태를 잠깐 바꿔 쓰고 끝나면 되돌리기 때문에,
  만들기 화면이 열려 있어도 서로 간섭하지 않습니다.
- 조각 위치는 **바닥 상자 기준**(0,0)입니다. 바닥은 `left:20 top:238`에 있고
  한 조각은 360 × 420이라, 놓을 수 있는 범위는 `0…825 × 0…420`입니다.
  두 줄이 서로 겹치지 않게 바닥 높이를 840으로 잡았습니다 — 420씩 딱 두 줄입니다.
- 시안 02번의 `Apartment, Siute, etc`는 오타로 보고 **Suite**로 적었습니다.
- 3단계 카드 칸은 보여주기용입니다. 아무 데도 보내지 않고 저장도 하지 않으며,
  브라우저가 실제 카드번호를 채워 넣지 않도록 `autocomplete`도 켜지 않았습니다.
- 아이콘은 `Icon/`의 SVG를 `icons.js`에 문자열로 넣고 `fill="currentColor"`로
  바꿔 색을 따라오게 했습니다. 카메라와 X 두 개는 폴더에 없어서 같은 선 두께로
  직접 그렸습니다.
- 헤더 아이콘은 글자처럼 baseline에 맞추면 옵션바 전체가 6.5px 내려앉습니다
  (아이콘이 대문자보다 baseline 위로 높아서). `align-self:flex-start`로 두고
  `top`으로 맞췄습니다.
- 모바일의 파형 캔버스도 `left`/`right`로 늘이지 않고 폭을 직접 줍니다. 위의
  결과 캔버스와 같은 이유입니다 — 치환 요소라 `width:auto`면 width **속성**을
  고유 크기로 잡고 `right`를 버립니다. 늘여 놨더니 390 화면에서 466으로
  삐져나왔습니다.
- 모바일 아래 바의 치수는 `Mobile_LiveSound`에서 픽셀로 쟀습니다 (이미지 폭
  783 = 아트보드 390의 2.008배). 탭 글자 cap 17.4 → **24px**, Sound 박스
  87 × 36, 프로필 23 × 25, 장바구니 24 × 26, 바 아래 여백 34.
- `About` 탭은 요청에 따라 넣지 않았습니다.
